# 附录 C：术语与状态速查

| 术语 | 本书中的含义 | 常见误读 |
| --- | --- | --- |
| 业务任务 | 用户希望完成的业务目标 | 一定等于一次 HTTP 请求 |
| 请求 | 一次入口调用 | 一定只有一次上游尝试 |
| 尝试 | 对一个选定上游发起的一次调用 | 换上游后仍是同一次计费执行 |
| 能力 | 经定义和验证的协议或功能约束 | 模型名字相同就相同 |
| 提交点 | 对另一个参与方形成可观察事实的时刻 | 响应头、首个事件与业务成功相同 |
| 完整结束 | 满足该协议的终止与验证条件 | HTTP 200 就已经完成 |
| unknown | 缺少判断执行或用量所需的证据 | 失败且费用为零 |
| 预留 | 为新请求保留的容量或预算 | 已确认消耗 |
| 结算 | 按可信合同记录已经发生的用量 | 根据输出长度猜测真实账单 |
| 对账 | 使用权威补充证据处理差异或未知 | 到时间后把记录自动清零 |
| 准入 | 发起资源消耗前的身份、容量与预算决策 | 只检查 QPS |
| 背压 | 下游容量不足时对上游生产或读取施加限制 | 自动保证远程不再计费 |
| 取消 | 请求停止继续进行的意图与传播机制 | 业务回滚和退款 |
| 幂等 | 重复相同操作的预期效果与一次相同 | 重复执行没有资源成本 |
| 故障切换 | 在合同允许的范围选择另一执行候选 | 任意异常都可透明重放 |
| SSE | 按规范编码的单向事件流格式 | 一个网络分片就是一个 token |
| credit | 实验合同中的 UTF-8 文本字节单位 | 真实模型 token 或货币 |
| 审计 | 保存行为、身份与状态转换的可核查记录 | 默认保存完整提示词与密钥 |

实验中的 token 事件表示一段文本增量；usage 表示实验字节用量；done 表示协议结束。只有事件、输入输出量和状态均满足约定，才能确认结算。真实供应商的事件名称、累计规则与结束条件应由适配器分别验证。

生产改造时，可以保留这些概念，但必须重新验证实现保证。持久化、多实例、真实供应商认证、TLS、账单对账和运行恢复均超出单进程本地实验的完整覆盖范围。
